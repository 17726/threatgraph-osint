# GraphRAG 架构借鉴分析

## 资料来源

1. Microsoft GraphRAG 文档：https://microsoft.github.io/graphrag/
2. Microsoft GraphRAG GitHub：https://github.com/microsoft/graphrag
3. Microsoft Research GraphRAG 项目页：https://www.microsoft.com/en-us/research/project/graphrag/

## 项目定位

GraphRAG 是一种图增强检索生成方法，核心流程是从原始文本中抽取知识图谱，构建社区层级和社区摘要，再利用这些结构增强问答和分析。它关注的是大规模文本语料的结构化发现，而不是传统 CTI 平台。

它对本项目有直接参考价值，因为课程要求正是从 OSINT 非结构化文本中抽取实体、关系、行为模式并生成报告。

## 与本项目架构对比

相同点：

1. 都从非结构化文本开始。
2. 都需要文档切块、实体抽取、关系抽取和图谱构建。
3. 都使用 LLM 参与信息抽取和总结。
4. 都希望用图结构提升分析和报告质量。

GraphRAG 的优势：

1. 文本到图谱的流水线完整，适合大规模语料分析。
2. 社区发现和社区摘要适合从复杂图谱中总结主题。
3. 图结构能辅助 LLM 回答更综合的问题。
4. 对“从资料中发现潜在关系”的课程表达很有帮助。

GraphRAG 相对本项目的不足：

1. 完整 GraphRAG 流程偏重，成本和调试复杂度高。
2. 它是通用文本图谱方法，不内置 CTI 语义约束和 MITRE ATT&CK 结构。
3. 社区摘要不等同于可审计证据链，课程答辩仍要能回到原文证据。
4. 如果直接引入框架，容易失去对实体类型、关系类型和证据字段的控制。

本项目当前架构的优势：

1. 领域 schema 更明确，实体和关系类型受控。
2. SQLite 保存所有中间结果，便于复现和评测。
3. `evidence` 表能保证报告可追溯。
4. MVP 只覆盖 3 个目标组织，复杂度可控。

## 是否应该学习

应该学习 GraphRAG 的流程思想，但 P0 不建议直接引入完整 GraphRAG 框架。

建议学习：

1. 文档切块后抽取实体和关系。
2. 图谱不是展示附件，而是分析和报告生成的中间结构。
3. 对每个目标组织生成行为模式摘要。
4. 后续可用图社区或子图摘要提升报告质量。

不建议学习：

1. P0 不做社区发现和多层社区摘要。
2. P0 不做开放式 GraphRAG 问答。
3. 不让 LLM 摘要覆盖证据事实。

## 阶段与优先级建议

### 优先级 P0

可吸收：

1. 固化 `documents -> chunks -> extracted_entities/extracted_relations -> canonical graph` 流程。
2. Prompt 输出必须是结构化 JSON。
3. 抽取结果进入候选层，再经归一化进入事实图谱。
4. 报告生成使用图谱、行为分析和 evidence，而不是只总结全文。

不放入 P0：

1. 社区检测。
2. 大规模索引。
3. 图增强问答界面。

### 优先级 P1

可吸收：

1. 针对目标组织生成子图摘要。
2. 基于图谱路径生成解释性报告段落。
3. 引入“候选推断关系”的人工确认或规则确认流程。
4. 对复杂图谱支持按主题、攻击阶段、技术簇筛选。

### 优先级 P2

可吸收：

1. 图社区发现和社区摘要。
2. 面向图谱的自然语言问答。
3. 跨组织相似行为发现，例如 APT28 与 Kimsuky 是否共享技术链。
4. 用图结构辅助 LLM 生成更可解释的预警建议。

## 结论

GraphRAG 是本项目 LLM 抽取和报告生成链路的重要参考，但应该被“领域化”和“轻量化”。优先级 P0 学流程，增强阶段再考虑子图摘要、图增强问答和社区分析。
